# การประเมินผลหลายโดเมน

การประเมินผลในขั้นที่ 20 ตรวจสอบว่าแกนหลักและ SDK สาธารณะชุดเดียวของ AgentTree สามารถกำหนดค่าให้กับลำดับงานด้าน IT/เทคนิค, HR/เอกสาร และธุรกิจ/ผลิตภัณฑ์ได้หรือไม่ อินพุตและเอาต์พุตเป็นข้อมูลสังเคราะห์ provider ให้ผลแน่นอน และไม่มีการติดต่อบริการภายนอก

รันจาก root ของ repository:

```sh
python evaluation/run_evaluation.py
```

ตัวรันประมวลผลสองสถานการณ์ต่อโดเมนและเขียน JSON ที่เรียงลำดับแล้วไปยัง `evaluation/results.json` โดยวัดเงื่อนไขต่อไปนี้อย่างตรงตัว:

- การนำ `AgentTree.run(Task)` กลับมาใช้ซ้ำ โดยโค้ดเฉพาะโดเมนอยู่นอกแกนหลัก
- การลงทะเบียน/เรียกใช้ Manager, Specialist และความสามารถใหม่
- การกำหนดเส้นทาง Manager และ Specialist ตามที่คาด โดยไม่รวมเอเจนต์ที่ไม่เกี่ยวข้อง
- ผลลัพธ์ที่ผ่าน normalization เทียบเท่ากันภายใต้ตัวตน `MockProvider` ที่ต่างกัน
- เหตุการณ์หลักของ trace ที่เป็นของ Task และเรียงตามลำดับ
- การเรียก `FunctionTool` ออฟไลน์อย่างชัดเจน
- ความเทียบเท่าเชิง semantics ระหว่าง sequential/LangGraph ที่เป็นตัวเลือก

เอกสารที่สร้างขึ้นมีฟิลด์ระดับบนสุด `schema_version`, `framework_api`, `metric_definitions`, `scenarios` และ `overall` แถวของแต่ละสถานการณ์เก็บ ID/ชื่อที่คาดและสังเกตได้ การกำหนด provider ผลลัพธ์ normalized ตำแหน่ง trace และหลักฐานเครื่องมือ สำหรับนำไปใช้ในตารางรายงานภายหลัง

ผลลัพธ์เหล่านี้แสดงคุณสมบัติของเฟรมเวิร์กเฉพาะใน fixture ที่กำหนดไว้ ไม่ได้วัดความฉลาดของโมเดล ความถูกต้องเชิงความหมายในทุกโดเมน ประสิทธิภาพ ความสามารถในการปรับขนาด หรือความน่าเชื่อถือระดับ production ดู [วิธีการประเมินผลฉบับเต็ม](../evaluation/README.md)
