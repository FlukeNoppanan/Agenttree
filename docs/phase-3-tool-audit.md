# Phase 3 tool audit (pre implementation)

The existing `BaseTool` contract exposes an ID, name, description, `ToolInputSpec`, metadata, and synchronous `invoke`. `FunctionTool` wraps Python callables; `MCPTool` implements the same contract. `ToolRegistry` indexes registered tools by ID and normalized name. `ToolBindingRegistry` stores ordered agent ID to tool ID pairs, although its methods and documentation call the agent a specialist. `AgentTree.bind_tool` currently accepts only registered specialists.

The current specialist lifecycle stops at manual invocation: a host registers a tool, binds it to a specialist, and may construct `ToolExecutor(registry, bindings)` and call `execute(specialist=..., tool_id=..., arguments=...)`. The executor resolves the tool, checks the assignment only when bindings were supplied, calls `invoke`, checks the returned tool ID, and optionally appends a trace event. `FunctionTool` checks Python signature binding but does not validate JSON types or value sizes. Callable failures become `ToolResult` failures containing the original exception text. Tool metadata and error text are copied into manual trace events.

`AgentTree.run` does not use `ToolExecutor`. Provider requests contain no tool definitions or tool history. The compatible adapter extracts OpenAI style tool calls as raw dictionaries but rejects a response with no text. Gemini does not translate function calls. No model driven tool request, tool result roundtrip, or multiple tool rounds exist in the workflow. Therefore the provider never learns the specialist's assigned tools, and a tool result never returns to the model. Tool calling is neither a complete native flow nor an existing prompt protocol. Root and Manager provider strategies make direct single generation calls; Specialist execution also makes one generation call. No HTTP tool implementation exists. MCP tools already share `BaseTool` and should remain transport adapters.

The trace has manual `orchestration.tool_execution_*` labels, but no correlated call ID, role, budget, timeout, or result size. Existing token usage counts provider responses, not tool work. Tool assignment is independent of provider binding already, which is the useful basis for a shared runtime.

The implementation must make assignment enforcement unconditional for model driven calls, validate arguments before invocation, return safe structured failures to the model, bound calls and rounds per agent execution, and keep trace data free of raw arguments, outputs, exceptions, and tool metadata.
